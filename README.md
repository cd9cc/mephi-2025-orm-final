Учебная платформа на Spring Boot 4.0.0: курсы, модули, уроки, материалы, запись студентов,
задания, оценивание, викторины и отзывы. Приложение предоставляет JSON REST API и хранит данные
в PostgreSQL.

## Запуск

С помощью docker compose:

```bash
docker compose up --build
```

Альтернативный вариант - локально:

Требуются JDK 17+ и PostgreSQL.

Необходимо создать базу learning и пользователя learning с собственным паролем через клиент
PostgreSQL
либо подготовить .env, как описано выше, и запустить только БД:


Необходимо задать переменные в настройках окружения процесса:

| Переменная             | Значение                                            |
|------------------------|-----------------------------------------------------|
| DB_URL                 | jdbc:postgresql://localhost:5432/learning           |

### Аутентификация и авторизация

По умолчанию включена сессионная аутентификация Spring Security. Новый пользователь
регистрируется как студент:

```http
POST /api/auth/register
Content-Type: application/json

{"name":"Sam Lee","email":"sam@example.test","password":"strong-password"}
```

Вход создаёт HTTP-сессию и возвращает профиль пользователя:

```http
POST /api/auth/login
Content-Type: application/json

{"email":"sam@example.test","password":"strong-password"}
```

Cookie `JSESSIONID` необходимо передавать в последующих запросах. `POST /api/auth/logout` завершает
сессию.
Открыты только чтение каталога и курсов; операции создания и изменения контента требуют роли
`TEACHER` или `ADMIN`, удаление и управление пользователями — `ADMIN`. Для локального запуска
без защиты можно задать `SECURITY_ENABLED=false`; тестовый профиль использует это значение.

## 1. Модель данных

Реализованы 16 JPA-сущностей с генерируемыми первичными ключами и внешними ключами.
Связи 1-1 представлены парами User–Profile и CourseModule–Quiz; 1-M — иерархией
Course–CourseModule–Lesson и дочерними заданиями, материалами и вопросами;
M-M — Course–Tag через таблицу course_tags. Связь студентов и курсов реализована
отдельной сущностью Enrollment с датой записи и статусом.

| Сущность       | Основные связи и ограничения                                                                                                                                                      |
|----------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| User           | Уникальный адрес электронной почты, приведённый к единому регистру и очищенный от пробелов по краям; роль STUDENT/TEACHER/ADMIN; обратная сторона связи «один к одному» с Profile |
| Profile        | Обязательный уникальный внешний ключ на User; принадлежит пользователю                                                                                                            |
| Category       | Уникальное название; на категорию ссылаются курсы                                                                                                                                 |
| Tag            | Уникальное название; обратная сторона связи «многие ко многим» с Course                                                                                                           |
| Course         | Обязательные преподаватель и категория; владеет модулями и таблицей связи с общими тегами                                                                                         |
| Enrollment     | Внешние ключи на студента и курс; уникальная пара; дата записи и статус                                                                                                           |
| CourseModule   | Обязательный курс; владеет уроками; обратная сторона необязательной связи «один к одному» с Quiz                                                                                  |
| Lesson         | Обязательный модуль; владеет заданиями и материалами                                                                                                                              |
| LessonMaterial | Обязательный урок; название и URL ресурса                                                                                                                                         |
| Assignment     | Обязательный урок; срок сдачи и максимальный балл                                                                                                                                 |
| Submission     | Обязательные студент и задание; уникальная пара; оценка отсутствует до проверки                                                                                                   |
| Quiz           | Обязательная уникальная ссылка на модуль; владеет вопросами                                                                                                                       |
| Question       | Обязательный тест; тип SINGLE_CHOICE/MULTIPLE_CHOICE; владеет вариантами ответа                                                                                                   |
| AnswerOption   | Обязательный вопрос; признак правильности используется только при расчёте баллов                                                                                                  |
| QuizSubmission | Внешние ключи на студента и тест; число правильных ответов, общее число вопросов и время прохождения; повторные попытки разрешены                                                 |
| CourseReview   | Внешние ключи на студента и курс; уникальная пара; оценка, комментарий и время создания                                                                                           |

Таблица связи `course_tags` не является отдельной JPA-сущностью. Модель содержит 16 классов
сущностей и охватывает связи «один к одному», «один ко многим» и «многие ко многим».
Название `CourseModule` исключает конфликт с `java.lang.Module`. Данные обратных связей,
для которых в предметной модели не нужны коллекции, запрашиваются через репозитории.

## 2. Репозитории и CRUD-операции

Для всех 16 сущностей созданы интерфейсы Spring Data JpaRepository в пакете repository.
Используются стандартные операции сохранения, чтения, обновления и удаления, запросы по именам
методов и граф загрузки курса. Бизнес-операции выполняются транзакционными сервисами.

Дочерние коллекции агрегатов используют `CascadeType.ALL` и `orphanRemoval`. Сервисные методы
обновляют обе стороны двунаправленных связей. Связи с общими категориями, преподавателями и тегами
не используют каскад `REMOVE`. Связи «курс → модуль → урок → задание/материал» и
«модуль → тест → вопрос → вариант ответа» образуют агрегаты.

Учебные записи, на которые существуют ссылки, сохраняются: перед удалением курса проверяются
записи студентов, все результаты и отзывы, а перед удалением вложенных объектов — результаты.
Отписка от курса не удаляет историю решений. Задания и тесты становятся недоступны для изменения
после появления результатов; оценки за решения по-прежнему может изменять преподаватель курса.
Пользователи, категории и теги, на которые существуют ссылки, защищены внешними ключами БД:
попытка удаления возвращает 409. Изменение роли после создания пользователя запрещено.

## 3. Управление курсами и контентом

Курс создаётся с обязательными преподавателем и категорией, а также необязательными тегами.
Сервис проверяет роль преподавателя. Поддерживаются изменение курса, фильтрация по категории,
добавление и редактирование модулей, уроков и материалов. Модули и уроки упорядочены по orderIndex.

GET /api/courses/{id} возвращает структуру курса, включая модули, уроки, задания и материалы.
Граф загрузки подгружает преподавателя, категорию и теги. Вложенные коллекции преобразуются
в DTO внутри транзакции, поэтому ответ доступен после закрытия сессии Hibernate.

## 4. Запись на курс

POST /api/courses/{id}/enrollments с телом {"studentId":2} записывает студента на курс.
Проверяются существование пользователя, роль STUDENT и отсутствие повторной записи.
Уникальная пара «студент — курс» дополнительно защищена ограничением базы данных.

GET /api/courses/{id}/enrollments возвращает записи студентов, GET /api/users/{id}/courses —
курсы студента. DELETE /api/courses/{id}/enrollments/{studentId} отменяет запись,
сохраняя историю решений и результатов тестов.

## 5. Задания и решения

Задание добавляется к уроку через POST /api/lessons/{id}/assignments. Указываются название,
описание, maxScore и необязательный dueDate в формате ISO-8601 UTC, например 2027-01-15T18:00:00Z.

Записанный на курс студент отправляет решение через POST /api/assignments/{id}/submissions:
{"studentId":2,"content":"Моё решение"}. Сервис отклоняет просроченные и повторные решения;
пара «студент — задание» уникальна в БД.

Решения доступны через GET /api/assignments/{id}/submissions и GET /api/users/{id}/submissions.
Оценка выставляется через PUT /api/submissions/{id}/grade с телом
{"teacherId":1,"score":95,"feedback":"Хорошая работа"}. Проверяются принадлежность преподавателя
курсу и диапазон от нуля до maxScore. Задание с решениями защищено от изменения и удаления;
преподаватель курса может менять оценку.

## 6. Тесты/викторины

Реализованы Quiz, Question, AnswerOption и QuizSubmission. Один модуль содержит не более одного
теста. POST /api/modules/{id}/quiz создаёт тест с вопросами и вариантами ответов.
Каждый вопрос содержит не менее двух вариантов. SINGLE_CHOICE требует ровно один правильный
вариант, MULTIPLE_CHOICE — хотя бы один.

Записанный студент проходит тест через POST /api/quizzes/{id}/submissions. Пример тела:

```json
{
  "studentId": 2,
  "answers": {
    "8": [
      20
    ],
    "9": [
      22,
      23
    ]
  }
}
```

Ключи answers — идентификаторы вопросов, значения — массивы идентификаторов выбранных вариантов.
Для SINGLE_CHOICE допускается не более одного выбранного варианта. Балл начисляется при точном
совпадении выбранного и правильного наборов; пропущенные и пустые ответы дают ноль.
Вопросы из другого теста и чужие варианты отклоняются.

Сохраняются score, totalQuestions и время прохождения; повторная попытка создаёт новый результат.
Результаты доступны через GET /api/quizzes/{id}/submissions, GET /api/users/{id}/quiz-results
и GET /api/courses/{id}/quiz-results. DTO чтения теста скрывает признаки правильности ответов.
После первого результата тест нельзя изменить или удалить. Ограничение времени попытки
и история выбора отдельных вариантов не реализованы.

## 7. Конфигурация приложения

Настройки вынесены в src/main/resources/application.properties.
Обычный профиль и dev используют PostgreSQL; dev включает демонстрационные данные.
Тестовый профиль находится в src/test/resources/application-test.properties.

| Переменная             | Значение по умолчанию                     | Назначение                                   |
|------------------------|-------------------------------------------|----------------------------------------------|
| DB_URL                 | jdbc:postgresql://localhost:5432/learning | JDBC-подключение                             |
| DB_USER                | learning                                  | Пользователь БД                              |
| DB_PASSWORD            | пустое значение                           | Пароль БД                                    |
| PORT                   | 8080                                      | HTTP-порт                                    |
| DDL_AUTO               | update                                    | Управление схемой Hibernate                  |
| DEMO_ENABLED           | false                                     | Начальное заполнение                         |
| SPRING_PROFILES_ACTIVE | не задано                                 | Профиль приложения; dev включает демо-данные |

Docker Compose читает .env; локальный Java-процесс использует переменные своего окружения.
Пароль задаётся пользователем и не зашит в Java-код. Hibernate обновляет схему при запуске;
для рабочей среды потребуются версионируемые миграции.

## 8. Интеграционное тестирование CRUD

PlatformIntegrationTest проверяет сохранение и чтение структуры курса, обновление и фильтрацию,
каскадное сохранение и удаление, профили, материалы, общие теги, ограничения уникальности
и защиту связанных данных. Отдельно проверяются LazyInitializationException для отсоединённой
сущности и доступность DTO после завершения транзакции сервиса.

По умолчанию используется H2 в режиме совместимости с PostgreSQL и схема create-drop.
Запуск только этого набора из корня проекта:

```text
./gradlew test --tests "*PlatformIntegrationTest"
```

Для проверки на PostgreSQL необходимо создать отдельную базу learning_test и задать параметры в
окружении процесса:

| Переменная       | Значение                                       |
|------------------|------------------------------------------------|
| TEST_DB_URL      | jdbc:postgresql://localhost:5432/learning_test |
| TEST_DB_USER     | learning                                       |
| TEST_DB_PASSWORD | пароль тестовой базы                           |

```text
./gradlew test --tests "*PlatformIntegrationTest" --rerun-tasks
```

Тесты создают и удаляют схему, поэтому нужна отдельная тестовая база.
Для возврата к H2 удалите TEST_DB_URL, TEST_DB_USER и TEST_DB_PASSWORD из окружения процесса.
DemoDataIntegrationTest всегда использует собственную изолированную базу H2.

## 9. REST API для основных операций

Запросы и ответы используют JSON. Идентификаторы генерируются базой данных: берите их из ответов
API. Создание возвращает **201**, чтение и обновление — **200**, удаление — **204**. Некорректные
данные приводят к ответу **400**, отсутствие сущности — **404**, попытка оценивания другим
преподавателем — **403**, дубликаты и удаление защищённых записей — **409**. Ошибки возвращаются в
формате RFC Problem Detail с полями `status`, `title`, `detail`.

| Метод              | Путь                                        | Операция                                                                                   |
|--------------------|---------------------------------------------|--------------------------------------------------------------------------------------------|
| GET / POST         | `/api/users`                                | Список / создание пользователей                                                            |

| GET                | `/api/users/{id}/courses`                   | Записи студента на курсы                                                                   |

### Примеры запросов

Запросы можно отправлять любым HTTP-клиентом с Content-Type: application/json.
Пример POST /api/courses; идентификаторы преподавателя и категории возьмите из ответов API:

```json
{
  "title": "JPA basics",
  "description": "Learn ORM",
  "teacherId": 1,
  "categoryId": 1,
  "tagIds": []
}
```

PUT курса использует те же поля. Отсутствующее или равное null поле tagIds означает отсутствие
тегов.
Для PUT /api/users/{id}/profile передайте {"bio":"Изучаю Java","
avatarUrl":"https://example.test/avatar.png"}.
Для POST/PUT материала — {"title":"Руководство","url":"https://example.test/guide"}.
Для POST отзыва — {"studentId":2,"rating":5,"comment":"Полезный курс"}:
студент должен быть записан на курс, повторный отзыв запрещён.

## 10. Дополнительная аналитика

Платформа предоставляет вычисляемую аналитику по успеваемости и тестированию:

- `GET /api/analytics/students/{studentId}` возвращает успеваемость студента по каждому записанному
  курсу (процент выполнения заданий, средний балл квизов и общий процент).
- `GET /api/analytics/ranking` строит рейтинг студентов по среднему проценту всех оценённых заданий
  и попыток квизов; ответ содержит позицию, число курсов и оценённых работ.
- `GET /api/analytics/quizzes` возвращает число попыток, число уникальных студентов, средний процент
  и долю успешных попыток (порог успеха — 60%).

Расчёты выполняются в read-only транзакции на основе `Enrollment`, `Submission` и `QuizSubmission`,
поэтому результаты учитывают только актуальные данные базы и не требуют предварительного
агрегирования.

## 11. Валидация ввода и обработка ошибок

Входные DTO в Requests используют Jakarta Bean Validation: обязательные поля, формат почты,
длины строк, положительные идентификаторы, диапазоны оценок, вложенную проверку вопросов
и вариантов. Сервисы проверяют роли, запись на курс, сроки, принадлежность вариантов вопросам,
уникальность и допустимость изменения учебных данных.

Ссылки на материалы, аватары и видео проверяются через @HttpUrl: допускаются абсолютные
HTTP/HTTPS URL с корректным хостом, без учётных данных и с портом от 1 до 65535, если он указан.
Относительные ссылки, пробелы и некорректные URI отклоняются. Для необязательных avatarUrl
и videoUrl можно передать null или опустить поле; URL материала обязателен.
Ошибка возвращает 400 с именем поля и описанием допустимого формата.

ApiExceptionHandler с @RestControllerAdvice централизованно преобразует ошибки в Problem Detail
с полями status, title и detail. Некорректный JSON, типы, даты и значения перечислений дают 400;
отсутствующая сущность — 404; оценивание чужим преподавателем — 403; дубликаты и конфликты
внешних ключей — 409. SQL-подробности конфликтов не передаются клиенту.

## 12. Предзаполнение данными

DemoData выполняет начальное заполнение в транзакции при включённом app.demo.enabled
и пустой таблице пользователей. Профиль dev включён в Docker Compose.
Повторный запуск с существующими пользователями не дублирует данные.

Создаются преподаватель Alex, студенты Sam и Dana, курс с двумя модулями, задание с оценённым
решением, тест с результатом, материал, профиль, тег и отзыв. После запуска запросите
GET /api/users и GET /api/courses, затем использовать полученные идентификаторы для просмотра
структуры курса, решений и результатов. Данные сохраняются в Docker-томе learning-data.

## 13. Тестирование (unit + интеграционные)

Тесты находятся в QuizScorerTest, PlatformIntegrationTest, DemoDataIntegrationTest,
HttpUrlValidationTest и AuthenticationIntegrationTest. AuthenticationIntegrationTest запускается
с включённой защитой и проверяет отказ неаутентифицированному запросу, регистрацию и вход
с созданием HTTP-сессии, а также запрет создания курса для пользователя с ролью STUDENT.
Параметризованные проверки URL охватывают корректные ссылки,
недопустимые схемы, хосты, порты, относительные пути и необязательные поля;
HTTP-тест проверяет ответы 400 в формате Problem Detail и сохранность данных.
Модульные тесты проверяют расчёт баллов, неправильные и пропущенные
ответы, множественный выбор. Интеграционные проверяют CRUD, каскады, бизнес-ограничения,
запись и отписку, задания и оценивание, викторины, отзывы, профили, демо-данные и HTTP API.
Для HTTP-проверок запускаются контекст Spring и настоящий сервер.

Для полного набора достаточно JDK; отдельная PostgreSQL по умолчанию не требуется:

```text
./gradlew test
```

Отчёт: build/reports/tests/test/index.html. CI выполняет тесты с H2 и основной интеграционный
набор с PostgreSQL 17.

## 14. Архитектура и качество кода

- `entity`: 16 JPA-сущностей с генерируемыми идентификаторами, обязательными внешними ключами,
  уникальными адресами почты и уникальными парами для записей на курс, решений и отзывов. Для
  коллекций явно задана загрузка LAZY.
- `repository`: интерфейсы Spring Data `JpaRepository` для всех сущностей, запросы по именам методов
  и граф загрузки курса.
- `service`: бизнес-операции в транзакциях, валидация на уровне сервисов и преобразование сущностей
  в DTO. Связанные данные для HTTP-ответов читаются до завершения транзакции.
- `api`: проверяемые входные данные, DTO ответов, REST-контроллеры и централизованная обработка
  ошибок в формате Problem Detail.
- `config`: необязательное заполнение демонстрационными данными в транзакции.

### Транзакции и загрузка

Сервисные классы используют транзакции только для чтения при запросах и транзакции с возможностью
записи при изменениях. Объекты ответов создаются внутри этих транзакций; Open Session in View
отключён настройкой `spring.jpa.open-in-view=false`. Граф загрузки курса подгружает преподавателя,
категорию и теги; упорядоченные вложенные коллекции обходятся при открытой сессии. Пакетная загрузка
Hibernate уменьшает затраты на загрузку коллекций без объединения нескольких коллекций типа bag
в один результат с декартовым произведением строк.

При прямом обращении к репозиторию возвращается курс с неинициализированной коллекцией модулей.
Доступ к ней после завершения транзакции репозитория вызывает `LazyInitializationException`.
Интеграционный тест специально проверяет это поведение, а затем подтверждает, что вложенный
неизменяемый DTO, возвращённый `CourseService`, доступен после завершения транзакции сервиса.

Ограничения уникальности в БД предотвращают дублирование записей на курсы, решений и отзывов,
даже если два одновременных запроса прошли предварительную проверку. При нарушении ограничений
HTTP-клиент получает код 409 без подробностей SQL. Внешние ключи дополнительно защищают от удаления
данных, на которые существуют ссылки. Поддержка конкурентного редактирования и версионирование
выходят за рамки учебного проекта.

## 15. Автоматизация и DevOps

Dockerfile использует многоэтапную сборку: Gradle собирает JAR, затем
приложение запускается в JRE 21 от пользователя без прав root.
Docker Compose запускает PostgreSQL 17, ожидает его готовности по healthcheck
и хранит данные в постоянном томе learning-data.

GitHub Actions в .github/workflows/ci.yml запускается при push и pull_request:
проверяет Java-код, собирает приложение и выполняет тесты на H2 и PostgreSQL 17.
Отчёты тестов и Checkstyle сохраняются как артефакты. Автоматическое развёртывание не настроено.

Checkstyle проверяет код приложения и тестов по config/checkstyle/checkstyle.xml;
нарушения приводят к ошибке сборки. Отдельный запуск:

```text
./gradlew checkstyleMain checkstyleTest
```

Проверка также включена в задачи check и build. Отчёты HTML/XML находятся
в build/reports/checkstyle.

Spotless форматирует Java-код приложения и тестов с помощью Google Java Format
(стиль AOSP, отступ 4 пробела), удаляет неиспользуемые импорты и лишние пробелы.
Применить форматирование:

```text
./gradlew spotlessApply
```

Проверить форматирование без изменения файлов:

```text
./gradlew spotlessCheck
```

spotlessCheck автоматически входит в check и build, поэтому выполняется и в CI.
Checkstyle проверяет правила качества кода; Spotless исправляет форматирование.

## 16. Email-уведомления

Платформа поддерживает уведомления студентов по электронной почте:

- после добавления задания письмо отправляется всем студентам с активной записью на курс;
- после проверки работы письмо отправляется автору работы и содержит оценку, максимальный балл и
  комментарий преподавателя.

Для включения отправки необходимо настроить SMTP через переменные окружения:

| Переменная           | Назначение                                                |
|----------------------|-----------------------------------------------------------|
| `MAIL_HOST`          | SMTP-сервер                                               |
| `MAIL_PORT`          | SMTP-порт, по умолчанию `587`                             |
| `MAIL_USERNAME`      | Имя пользователя SMTP                                     |
| `MAIL_PASSWORD`      | Пароль SMTP                                               |
| `MAIL_SMTP_AUTH`     | SMTP-аутентификация, по умолчанию `true`                  |
| `MAIL_SMTP_STARTTLS` | STARTTLS, по умолчанию `true`                             |
| `MAIL_FROM`          | Адрес отправителя, по умолчанию `no-reply@learning.local` |

Пример запуска с SMTP-конфигурацией:

```bash
MAIL_HOST=smtp.example.com \
MAIL_PORT=587 \
MAIL_USERNAME=learning@example.com \
MAIL_PASSWORD=secret \
MAIL_FROM=learning@example.com \
./gradlew bootRun
```

Если SMTP не настроен или доставка письма завершилась ошибкой, операция добавления задания или
выставления оценки всё равно сохраняется.
